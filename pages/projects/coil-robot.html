COIL Robot Command & Control

🏆 Canada vs Netherlands — Won C++ TCP/UDP REST API Crow Winsock

Overview

Built as part of a COIL (Collaborative Online International Learning) program pairing Canadian and Dutch students. Our team won. The project is a full robot remote control system — a C++ webserver that accepts commands from a browser GUI, serializes them into a custom binary protocol, and transmits them to a physical robot or simulator over TCP/UDP.

Architecture

Browser GUI → Crow REST API → PktDef (packet builder) → MySocket (TCP/UDP) → Robot/Simulator ← Telemetry & ACK ←
  • PktDefLib — static library implementing the custom packet protocol: headers, CRC, serialization/deserialization
  • MySocket — static library wrapping Winsock for TCP/UDP client & server communication
  • Webserver — Crow REST API on port 8080 serving the browser GUI and routing commands to the robot
  • PktDefTests + mysocketTests — MSTest unit test suites for both libraries

Packet Protocol

| PktCount (2 bytes) | Flags (1 byte) | Length (1 byte) | Body (variable) | CRC (1 byte) |

Commands: DRIVE (forward/back/left/right), SLEEP, TELEMETRY. Responses: ACK / NACK.

REST API

  • GET / — serves the browser GUI
  • POST /connect/<ip>/<port> — connect to robot via UDP (29500) or TCP (29000)
  • PUT /telecommand/ — send drive or sleep command
  • GET /telementry_request/ — request housekeeping telemetry
  • POST /routing_table/ — forward commands through a middle instance to another GUI
  • GET /log — rolling JSON log of TX/RX packets

Features

  • Drive forward, backward, left, right with configurable duration and power
  • Sleep command and telemetry request
  • Command routing — forward commands through a middle server instance to another GUI
  • Physical robot connection over UDP or TCP depending on port
  • Rolling packet log visible in the browser
  • Full MSTest unit test coverage for both PktDef and MySocket
